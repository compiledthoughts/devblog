Glossary · Model Internals

Terms You'll See in Every Experiment

May 25, 2026 Qwen3.6 35B-A3B · 19.4 GB GGUF RTX 5060 Ti
A clean glossary for the terms that appear in every experiment post: token, block, MoE, attention, expert, weight, tensor, GGUF, quantization. Starting from zero. No assumed knowledge.

The Model

The model takes a token as input. Produces the next token as output. Does this one token at a time.

Token

A token is a piece of text. Not always a whole word.

"Hello world" → ["Hello", " world"]       = 2 tokens
"transformer" → ["transform", "er"]       = 2 tokens
"I" → ["I"]                               = 1 token

Qwen3.6 35B knows 248,320 different tokens.

Block

The model processes each token through a series of identical processing stages. Each stage is called a block (also called a layer — same thing).

Qwen3.6 35B has 40 blocks. Every token passes through all 40 blocks in order.

Token → Block 0 → Block 1 → Block 2 → ... → Block 39 → Next token predicted

In llama.cpp / GGUF files, blocks are named:

blk.0   = Block 0 (first)
blk.1   = Block 1
...
blk.39  = Block 39 (last)

Inside Each Block — Two Things

Block N
├── Attention    ← token looks at all previous tokens
└── MoE          ← token gets processed by specialists

Attention

Let's the current token "look back" at everything said before. Produces the KV cache (Keys and Values — the memory of what was said).

Every token. Every block. Always runs. Cannot be skipped.

MoE (Mixture of Experts)

Instead of one big calculator — 256 small specialist calculators called experts.

A router decides which 8 experts are most relevant for this token. Only those 8 run. The other 248 do nothing.

Block 0 MoE:
  Router: "token is about Python code → use experts 12, 47, 89, 103, 156, 201, 234, 247"
  Expert 12:  runs → produces output
  Expert 47:  runs → produces output
  ...8 total...
  Experts 0-11, 13-46, 48-88...: do nothing this token

Expert

One specialist calculator. Has three weight matrices:

Expert 47 in Block 0:
  gate_proj  ← first transformation
  up_proj    ← second transformation
  down_proj  ← final transformation

Each matrix is a 2D grid of numbers the model learned during training.

Weight

A number the model learned during training. Weights don't change during inference. They're stored in the GGUF file on disk.

Tensor

A tensor is just a multi-dimensional array of weights.

1D tensor (vector):   [1.2, 3.4, 5.6, 7.8]
2D tensor (matrix):   [[1.2, 3.4], [5.6, 7.8]]
3D tensor:            [[[...], [...]], [[...], [...]]]

In your model, each expert has 3 tensors (gate, up, down).

Merged Tensor

In your GGUF file, all 256 experts in a block are stored together in one big tensor instead of separately.

blk.0.ffn_gate_exps.weight
= one tensor containing gate_proj for ALL 256 experts
Shape: [256, 512, 2048]
        ^^^  ^^^  ^^^^
        256 experts
             512 FFN hidden dim
                  2048 model dim

To get expert 47's gate weights → slice row 47:

blk.0.ffn_gate_exps.weight[47, :, :]

GGUF

The file format that stores the model. Contains:

  • Metadata (model name, architecture, hyperparameters)
  • All tensors stored sequentially as binary data

Your model file: Qwen3.6-35B-A3B-MTP-IQ4_XS.gguf = 19.4 GB

Quantization

Weights are originally 32-bit floats (4 bytes each). Quantization compresses them to fewer bits to save space with minimal quality loss.

Your model uses:

IQ4_XS  ← ~4.25 bits per weight (gate, up experts)
Q5_K    ← ~5.5 bits per weight (down experts — higher quality)
